## 二、器件之间的配合关系

| 环节   | 涉及器件                    | 说明                                        |
| ---- | ----------------------- | ----------------------------------------- |
| 数据采集 | DHT11 + GY-302 + MQ-135 | 温湿度（单总线）、光照（I2C）、空气质量（ADC 模拟量）            |
| 现场显示 | OLED SSD1306            | 与 GY-302 共用同一条 I2C 总线（地址 0x3C 与 0x23 不冲突），需上传驱动 `ssd1306.py` |
| 自动控制 | 继电器 + 5V 风扇             | 温度 >35℃、空气 >4000 或湿度 >85% 时继电器吸合给风扇通电；风扇由独立 5V 电源供电 |
| 声光报警 | 有源蜂鸣器                   | 任一指标超限即**持续鸣叫**，环境恢复正常后自动停止（有源蜂鸣器自带震荡电路，无需 PWM） |
| 联网上报 | ESP32-S3 内置 WiFi        | 通过 MQTT 上报 OneNET，再由后端拉取入库                |

## 三、接线参考（对应 `esp32/config.py` 默认引脚）

```
ESP32-S3-N16R8（44 引脚板）
┌──────────────────┐
│  3V3   ──────────┼──── VCC：DHT11 / GY-302 / OLED / MQ-135 / 继电器 / 蜂鸣器
│  GND   ──────────┼──── GND：所有模块共地（必须共地！）
│  GPIO4 ──────────┼──── DHT11 DATA
│  GPIO9 ──────────┼──── I2C SCL（GY-302 + OLED 共用）
│  GPIO8 ──────────┼──── I2C SDA（GY-302 + OLED 共用）
│  GPIO1 ──────────┼──── MQ-135 AO（ADC1_CH0）
│  GPIO5 ──────────┼──── 继电器 IN（低电平触发）
│  GPIO6 ──────────┼──── 蜂鸣器 I/O（低电平触发）
└──────────────────┘

风扇（5V）：【不要从开发板 5V 取电】，必须用独立 5V 电源（充电宝/充电头），
           否则风扇电流会拉低板子电压导致主控复位。
     接线：独立电源正极 ─── 风扇红线
           风扇黑线 ─────── 继电器 COM
           继电器 NO ────── 独立电源负极
     （继电器只当"开关"串在回路里；独立电源无需与开发板共地）
```

> 接线提示（**本部分很重要，接错会烧板子或不工作**）：
>
> 1. **GPIO26\~GPIO32 是 SPI0/1 专用，连接模组内置 Flash 与 PSRAM**；**GPIO33\~GPIO37 在八线（Octal）SPI 模式下是高 4 位数据线与 DQS，而 N16R8 的 8MB PSRAM 正是八线模式，所以这 5 个脚同样被占用**。这 12 个脚绝对不能外接器件，否则板子无法启动。本项目统一使用 GPIO1\~GPIO9，全部是安全引脚。
> 2. **GPIO19 / GPIO20 是 USB_D- / USB_D+**：芯片内置的「USB 串口/JTAG 控制器」和「USB OTG 控制器」共用这两个脚，不要外接器件；**GPIO43 / GPIO44 是 U0TXD / U0RXD**（串口0，下载与日志打印用），也不要用。
> 3. MQ-135 只有 **AO 需要接 MCU**（DO 可悬空不用）。按数据手册，ESP32-S3 有 ADC1（GPIO1\~GPIO10）和 ADC2（GPIO11\~GPIO20）两组 ADC，**ADC2 与 Wi-Fi 存在冲突，联网时必须用 ADC1**；本项目选用 GPIO1（即 ADC1_CH0）。程序把衰减设为 ATTN3（MicroPython 的 ATTN_11DB），**满量程约 2.9V**（手册表 5-6：ATTN0=0.85V、ATTN1=1.1V、ATTN2=1.6V、ATTN3=2.9V）。而 5V 供电的 MQ-135，其 AO 最高可达 5V，会严重超量程。**本项目实测把模块 VCC 接到开发板 3.3V 引脚**（最省事、无需分压电阻，灵敏度略降）；若改用 5V 供电，则必须在 AO 与 GPIO1 之间加电阻分压把电压压到 2.9V 以内。
> 4. **继电器和蜂鸣器都是低电平触发**：电平给 0 才动作。程序里已通过 `RELAY_ACTIVE_LOW / BUZZER_ACTIVE_LOW = True` 处理，无需手动改逻辑。
> 5. 继电器模块用 **3.3V 供电**即可驱动信号端；风扇那一路（5V）走继电器的 COM/NO 触点，**由独立 5V 电源供电、与开发板电源完全隔离**，避免风扇电流拉低开发板引起复位。注意继电器是"开关"必须串在回路里，风扇两根线不能都接在 COM/NO 上。
> 6. BH1750 和 OLED 都是 I2C 设备，可以挂在同一条 SCL/SDA 总线上（地址不同即可共存）。程序里用的是**软 I2C + 引脚内部上拉 + 50kHz**（实测硬件 I2C 扫不到该 OLED、100kHz 不稳定）。
> 7. **OLED 驱动 `ssd1306.py` 不属于固件内置库**，必须随工程上传到板子，否则报 `ImportError: no module named 'ssd1306'`。
> 8. **蜂鸣器采用「持续鸣叫」报警**：任一环境指标超限就一直响，直到环境恢复正常才停。若嫌吵，可调 `config.py` 里的阈值，或后续加一个手动消音按钮。
> 9. 面包板接线前先断电，接完检查一遍再插 USB 供电。DHT11 若读取不稳定，可在 DATA 与 3V3 之间加一个 4.7kΩ\~10kΩ 上拉电阻。
> 10. 开发板有**两个 Type-C 接口**，都能出串口，只是走线不同：**USB-OTG（USB）口走芯片内置的 USB 串口/JTAG，上电即出现串口，无需驱动**；**USB-ISP（UART）口走板载 CH340 转串口芯片，先装官方 CH340 驱动后显示 `USB-SERIAL CH340`**。两个口任选其一连接即可，烧录与串口调试都行。
> 11. 板载 **RST（复位）** 和 **BOOT（下载）** 两个按键：正常烧录时点 Thonny 的 Install 会自动进入下载模式；若固件刷坏了进不去，可按住 BOOT 再点一下 RST 手动进入下载模式。

## 四、到货后第一步

1. 先给 ESP32-S3 单独烧录 MicroPython 固件（见部署文档，务必下 **ESP32-S3** 版本固件，不能刷经典 ESP32 的）
2. 用 Thonny 的 REPL 验证串口能打印、能连上 WiFi
3. 再按接线参考逐个接传感器，每接一个就单独测试一次
4. 全部通过后，再整体运行 `main.py`
