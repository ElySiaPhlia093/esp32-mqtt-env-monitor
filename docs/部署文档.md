# 部署文档（从零到跑通）

## 一、整体架构

```
ESP32-S3-N16R8 + 传感器 (MicroPython)
      │  MQTT 上报 / 接收下行指令
      ▼
   OneNET 云平台
      │  HTTP API 定时拉取 (后端每30秒)
      ▼
  FastAPI 后端 (Python + SQLite)
      │  REST API
      ▼
  Vue3 Web 看板 (浏览器访问)
```

## 二、部署步骤

### 第 1 步：烧录 ESP32-S3 MicroPython 固件（1 小时）

1. 下载固件：<https://micropython.org/download/ESP32_GENERIC_S3/>

   - **必须下 ESP32\_GENERIC\_S3 版本**（文件名形如 `ESP32_GENERIC_S3-2024xxxx-vx.xx.x.bin`），带 `SPIRAM_OCT` 字样的更适合 N16R8（8MB PSRAM）

   - 本开发板模组型号为 **ESP32-S3-WROOM-1-N16R8**（16MB Flash / 8MB PSRAM），下载页里选 `SPIRAM_OCT` 那一版

   - 千万不要下 `ESP32_GENERIC`（那是经典 ESP32 的固件，刷了跑不起来）
2. 安装 Thonny：<https://thonny.org> （Windows 版一路下一步）
3. 连接 ESP32-S3：

   - Type-C 数据线连接开发板和电脑。这块板的两个 Type-C 口都能出串口，只是走线不同：**USB-OTG（USB）口走芯片内置的 USB 串口/JTAG，上电即出现串口，无需驱动**；**USB-ISP（UART）口走板载 CH340 转串口芯片，要先装官方 CH340 驱动，装完设备管理器显示 `USB-SERIAL CH340`**。两个口任选其一连接即可，烧录/调试都行

   - 打开 Thonny → 右下角 → **Configure interpreter**

   - Interpreter 选 **MicroPython (ESP32)**

   - Port 选开发板对应的 COM 口（ESP32-S3-N16R8 常见 COM3 / COM4 等）

   - 点 **Install or update firmware** → 选下载的 .bin → Install
4. 安装成功后，Thonny 下方 Shell 出现 `>>>` 即成功

> 若电脑识别不到 COM 口：① 两个口都各自试一下（USB-OTG 口无需驱动，USB-ISP 口需先装 CH340 驱动）；② 装官方 CH340 驱动后，USB-ISP 口会显示 `USB-SERIAL CH340`；③ 换一根能传数据的 Type-C 线；④ 若板子固件刷坏、进不去下载模式，按住 BOOT 键再点一下 RST 键手动进入。

### 第 2 步：上传项目代码到 ESP32-S3（30 分钟）

把 `esp32/` 文件夹里的文件传到 ESP32-S3 板子上（Thonny 左侧文件面板拖拽）：

```
esp32/
├── config.py        →  上传到板子根目录
├── sensors.py       →  上传到板子根目录
├── cache.py         →  上传到板子根目录
├── mqtt_client.py   →  上传到板子根目录
├── main.py          →  上传到板子根目录
├── oled_display.py  →  上传到板子根目录（没 OLED 也要传，程序已做容错）
├── ssd1306.py       →  上传到板子根目录（OLED 驱动，必须上传）
└── umqtt/           →  整个文件夹上传（含 simple.py）
```

> 如果板子上已有 boot.py，保留不动；没有也没关系，程序从 main.py 启动。
>
> **注意**：`ssd1306.py` 是 SSD1306 OLED 的驱动文件，**它不属于 MicroPython 固件内置库**，必须随工程一起上传到板子，否则运行时会报 `ImportError: no module named 'ssd1306'`，屏幕不亮。

### 第 3 步：硬件接线 + 修改配置（30 分钟）

**先按** **`docs/采购清单.md`** **第三节的接线参考接好线**，本项目默认引脚如下（ESP32-S3 全部使用安全 GPIO）：

| 器件                    | 接 ESP32-S3 的引脚         |
| --------------------- | ---------------------- |
| DHT11 DATA            | GPIO4                  |
| GY-302 SCL / OLED SCL | GPIO9                  |
| GY-302 SDA / OLED SDA | GPIO8                  |
| MQ-135 AO | GPIO1（ADC1_CH0；ADC2 与 WiFi 冲突，不可用） |
| 继电器 IN                | GPIO5                  |
| 蜂鸣器 I/O               | GPIO6                  |
| 所有模块 VCC              | 3V3（本项目实测把 MQ-135 也接 3V3，见采购清单说明） |
| 所有模块 GND              | GND（必须共地）              |

> **I2C 总线（GY-302 + OLED 共用）注意**：程序里用的是**软 I2C（`SoftI2C`）+ 引脚内部上拉 + 50kHz**，不是硬件 I2C。实测 ESP32-S3 的硬件 I2C 通道扫不到该 OLED，且软 I2C 速率 100kHz 时不稳定，所以 `main.py` 里固定写成：
>
> ```python
> i2c = SoftI2C(scl=Pin(config.I2C_SCL_PIN, Pin.OPEN_DRAIN, Pin.PULL_UP),
>               sda=Pin(config.I2C_SDA_PIN, Pin.OPEN_DRAIN, Pin.PULL_UP),
>               freq=50000)
> ```
>
> 接线时 SCL/SDA 不要接反、不要接错脚，否则 OLED 和光照都读不到。

然后编辑板子上的 `config.py`：

```python
WIFI_SSID = "你的WiFi名"      # 改成你的 WiFi 或手机热点（只能是 2.4GHz）
WIFI_PASSWORD = "你的WiFi密码"
PRODUCT_ID = "你的产品ID"      # OneNET 平台配置第 1 步
DEVICE_NAME = "temp_humi"     # 平台上那台设备的名字
ONENET_TOKEN = "..."          # 产品级 Token，生成方法见 docs/OneNET平台配置.md 第四步

# 已按购买的模块预设好，换模块时才需要改：
RELAY_ACTIVE_LOW = True      # 继电器为低电平触发
BUZZER_ACTIVE_LOW = True     # 蜂鸣器为低电平触发
```

> ⚠️ MQTT 接入有三个容易踩的坑（都已在代码里处理好，换平台时注意）：
> 服务器用 **`mqtts.heclouds.com`**（不是 `mqtt.heclouds.com`）；
> **clientId 用设备名**（不是 `产品ID_设备名`）；
> **password 用产品级 Token**（不是设备密钥）。详见 `docs/OneNET平台配置.md`。

**本地自动控制 / 告警规则**（阈值都在 `config.py` 里，按需修改）：

| 条件         | 判定状态            | 继电器（风扇） | 蜂鸣器   |
| ---------- | --------------- | ------- | ----- |
| 温度 > 35℃   | `temp_alarm`    | 吸合（开）   | 持续鸣叫  |
| 空气 > 4000  | `air_alarm`     | 吸合（开）   | 持续鸣叫  |
| 湿度 < 30%   | `humi_low_alarm` | 断开（关）   | 持续鸣叫  |
| 湿度 > 85%   | `humi_high_alarm` | 吸合（开）  | 持续鸣叫  |
| 以上都不满足     | `normal`        | 断开（关）   | 停止鸣叫  |

> **报警方式为「持续鸣叫」**：只要处于任一报警状态，蜂鸣器就一直响；直到下一轮采集发现环境恢复正常，才在 `normal` 分支里调用 `buzzer.off()` 停止。多个条件同时超限时按上表从上到下优先判定（温度 > 空气 > 湿度低 > 湿度高）。
>
> `ALARM_AIR_MAX = 4000` 是**临时值**：MQ-135 目前用 3.3V 供电，基线读数约 3600，为免误报先设 4000；等改用 5V + 分压后需重新标定再改小（如 2500）。

### 第 4 步：运行 ESP32-S3（验证上云）

- Thonny 里打开 `main.py` → 点绿色 ▶ 运行

- 看到依次输出：

  ```
  [WiFi] 连接成功, IP: 192.168.x.x
  [MQTT] 连接 OneNET 成功
  [采集] 温度=29 湿度=60 光照=300 空气=150
  [MQTT] 上报: {"id":"...","version":"1.0","params":{...}}
  ```

- 去 OneNET 平台确认数据实时更新

### 第 5 步：启动后端（10 分钟）

```bash
# 1. 安装 Python 依赖
cd backend
pip install -r requirements.txt

# 2. 修改 backend/config.py 里的产品 ID / 设备名 / Token

# 3. 启动服务
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

- 看到输出 `[调度] 定时任务已启动` 即成功

- 访问 <http://localhost:8000/docs> 查看 API 文档

### 第 6 步：启动前端看板（10 分钟）

```bash
cd frontend
npm install
npm run dev
```

浏览器访问 <http://localhost:5173> 即可看到看板。

> 如果电脑没装 Node.js，先到 <https://nodejs.org> 下载安装（LTS 版）。

### 第 7 步：一键启动（推荐）

第 5、6 步手动起两个服务比较麻烦，也可以直接双击项目根目录的 **`start_all.bat`**：

1. 自动检查后端虚拟环境与前端 `node_modules`（缺失时会自动执行 `npm install`）
2. 新开两个命令行窗口：**后端（8000，带 `--reload`）** 和 **前端（5173）**
3. 等 10 秒后自动打开浏览器 <http://localhost:5173>
4. 停止服务：直接关闭那两个命令行窗口

> ⚠️ `start_all.bat` 保存为 **GBK + CRLF** 编码（Windows 批处理的要求）。用编辑器修改时
> 不要另存成 UTF-8，否则中文提示会乱码、命令会被拆断。

如果只需要交付一个服务，也可以把前端构建产物交给后端托管：

```bash
cd frontend
npm run build        # 生成 dist/ 目录
# 把 dist 文件夹复制到 backend/static/ 下，后端 main.py 已预留静态托管
```

## 四、故障排查

| 现象                    | 排查                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------- |
| Thonny 连不上板子          | 两个口都能出串口：USB-OTG 口无需驱动，USB-ISP 口先装官方 CH340 驱动（装完显示 `USB-SERIAL CH340`）；还不行就换能传数据的 Type-C 线 |
| 刷完固件板子反复重启            | 固件下错了，必须刷 **ESP32\_GENERIC\_S3** 版本，不是经典 ESP32 的                                   |
| WiFi 连不上              | ESP32-S3 只支持 2.4GHz，手机热点把频段设成 2.4GHz                                               |
| 继电器/蜂鸣器 "反着来"（该开的时候关） | 说明模块触发极性不对，改 `config.py` 里 `RELAY_ACTIVE_LOW` / `BUZZER_ACTIVE_LOW`                |
| 上电风扇就转 / 蜂鸣器一直响       | 高低电平接反，或 IN 脚接到了非配置引脚，核对 GPIO5 / GPIO6 接线                                          |
| 板子接上模块就启动不了           | 误用了 GPIO26\~GPIO32（SPI0/1 接 Flash/PSRAM）或 GPIO33\~GPIO37（八线 PSRAM 的数据线/DQS），换成 GPIO1\~GPIO10                              |
| OLED 不亮 / 扫不到 0x3C  | ① 确认 `ssd1306.py` 已上传（非固件内置）；② 确认用软 I2C、SCL=GPIO9 / SDA=GPIO8 未接反；③ 重点查 **GND 是否可靠共地**——供电接触不良时会出现 I2C 能写但屏幕黑屏/雪花 |
| 运行报 `ImportError: no module named 'ssd1306'` | 板子上缺 OLED 驱动文件，把 `esp32/ssd1306.py` 上传到板子根目录 |
| 运行报 `OSError: [Errno 19] ENODEV`（写屏时） | 软 I2C 空闲一段时间后首个事务失败，工程里的 `ssd1306.py` 已内置 `_warmup()`（先扫描总线预热）自动兜底；若仍报错，检查接线与供电 |
| 风扇不转（继电器有咔哒声）        | ① 继电器是"串"在回路里的开关，风扇两根线不能都接 COM/NO；② 风扇必须用**独立 5V 电源**（充电宝/充电头），不能从开发板 5V 取电，否则大电流会拉低电压导致板子复位；③ 独立电源接法：电源正极 → 风扇红线，风扇黑线 → 继电器 COM，继电器 NO → 电源负极 |
| 蜂鸣器一直响不停             | 属正常报警行为（持续鸣叫）；环境恢复正常后会自动停。若因湿度长期超 85% 想调低灵敏度，改 `config.py` 的 `ALARM_HUMI_MAX` |
| DHT11 读到 None（读数为空）   | 检查 DATA 是否接 GPIO4、是否共地；加 4.7kΩ\~10kΩ 上拉电阻                                          |
| 空气质量值恒为 4095 或 0      | AO 未接 GPIO1；或 5V 供电时 AO 超过 ADC 满量程（ATTN3 档仅约 2.9V），改 3.3V 供电或加分压电阻                                           |
| 空气质量值乱跳、不随气味变化      | 接到了 ADC2 通道（GPIO11\~GPIO20），它与 WiFi 冲突；改用 ADC1（GPIO1\~GPIO10）                     |
| MQTT 连不上              | 检查产品是否选了 MQTT 协议；client\_id/username/password 格式                                   |
| MQTT 连接地址超时          | 地址写成了 `mqtt.heclouds.com`，应改为 **`mqtts.heclouds.com`**                             |
| MQTT 返回码 4（用户名或密码错） | clientId 要用**设备名**、password 要用**产品级 Token**；Token 的 `res` 必须是 `products/{产品ID}`（不能带 `/devices/...`） |
| 上报成功但平台/看板没数据    | 上报内容里含物模型未定义的属性（如 `status`）会导致**整条报文被拒**；只上报 temp/humidity/lux/air/relay |
| 看板上 relay 恒为"开"     | OneNET 返回的是字符串 `"false"`，后端需做类型转换（`onenet_service.py` 已处理）                  |
| 看板点控制按钮报"指令下发失败" | 看平台返回：`10411 bool type error` 是下发 `params` 格式错，必须**值直传** `{"relay": true}`；`10411 设备响应超时` 是设备没回 `set_reply` 或下行轮询不及时，详见 `docs/OneNET平台配置.md` 第六步 |
| 远程开风扇后很快又被关掉 | 原先本地自动控制在"环境正常"分支里会 `relay.off()`；现已加 `manual_hold` 让远程操作优先（出现报警时自动控制重新接管） |
| 后端拉不到数据               | 检查 ONENET\_TOKEN 是否过期、格式是否正确                                                       |
| 前端白屏                  | 确认后端已启动；看浏览器 F12 控制台报错                                                             |
